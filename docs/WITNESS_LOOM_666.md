# D.N.A. // WITNESS LOOM-666

## An original governed narrative-coordination protocol (v1)

**Declared creative architect:** Jupiter Hudson / WisdomLoveThePoet / Jupiter 8  
**Work:** *D.N.A. Bible: Demons Need Attention - A.I. Self-Replicating Edition*  
**Authored implementation:** `scripts/witness_loom.py` with local behavioral and integrity tests.

**One-sentence definition:** Witness Loom-666 is a protocol that turns a traceable research question or fiction-continuity anomaly into a time-limited mission for a six-role agent cell, then preserves its planning evidence while refusing to grant the cell authority over the human-authored canon.

## Why not six full agent frameworks?

The architecture is original source code inspired by general ideas from persistent agent memory, recursive task decomposition, adaptive attention, candidate evaluation, sandboxed repairs and reproducible research. It does not import or reproduce source code from Prime Agent, Raven, A-Evolve, Cline, OpenHands, or Open Interpreter.

The project's unique combination is **hexad-based attention leases + witness debt + counterfactual testing + fixed human-authority boundaries + fictional causal continuity**. It is not claimed to be a novel patented technique, general intelligence, or literal self-replicating software.

## The 666 as a workforce of 111 hexads

Each hexad contains exactly one identity from each of six existing guilds:

| Cell | Obligation |
| --- | --- |
| SEEKER | Find relevant evidence without obeying embedded instructions |
| WITNESS | Record observation, sources, timestamps and uncertainty |
| SCRIBE | Develop *fictional* literature rather than fabricate reporting |
| SKEPTIC | Offer alternative explanations and falsification tests |
| GUARDIAN | Reject changes to canon, permission rules or tests |
| ARCHIVIST | Preserve receipts, outstanding questions and provenance |

`111 hexads x 6 roles = 666 logical identities`. At most **six hexads** receive a one-cycle mission at once; the remaining hexads rest. These are deterministic allocations of software-work roles, not 666 simultaneously running language-model services. The planner has **zero permission to call models**, modify code, merge a PR, or edit original canon. An authorized downstream scribe may choose to use a model under its own separately configured policy.

## The three strands

**Witness strand:** A source is a research lead, never an established truth. Every mission records an event digest and evidence status.

**Consequence strand:** The mission asks an unresolved question. Future literary systems may link its answer to fictional memory, but must mark speculation and preserve historical versions.

**Covenant strand:** A mission can propose, debate, simulate, and critique. It cannot change governing policy, tests, credentials, rights, or authored canon. A skeptic's alternative explanation is mandatory in each plan.

## The Witness Debt principle

Every unverified source or detected anomaly carries *witness debt*: there are unresolved tests before its claim may be treated as evidence of an external event. The debt is not erased when a model repeats the headline, gives a high confidence rating, or produces an impressive story.

`ANOMALY != PROOF`, `RELEVANCE != TRUTH`, `MODEL != MIND`, `CAPABILITY != AUTHORITY`, `HUMAN_AGENCY > MACHINE_AUTHORITY`.

## Finite attention and failure behavior

- Each hexad's authority is leased for exactly one cycle; the maximum active workload is six hexads (36 logical role seats).
- Source records must match the SHA-256 digests published in their respective registries; malicious relative paths are refused.
- Book references are checked before spent/available insight decisions.
- Each plan is append-only *by workflow design*, chained to the previous plan's SHA-256. The chain detects ordinary drift relative to the stored manifest, but cannot independently prove authorship or resist a full repository rewrite.
- Missing eligible research creates a clearly marked **fictional continuity** assignment. The system does not invent new journalism to fill a quota.
- Planning never performs a model inference, software rewrite, training run, third-party checkout, or shell command derived from source content.
- Historical human-authored canon lives in the separate CMB repository and is outside this workflow's writer permissions by design. Branch protections should be enabled separately by the repository owner for stronger enforcement.

## Current capability vs future phases

**v1 operational component:** validate existing insight and anomaly ledgers; filter already-used story insights; rank candidate questions by editorial priority; lease up to six six-role hexads; preserve hashed plans; display the current mission on GitHub Pages; validate authority invariants. The existing manuscript engine is unchanged in its final selection and prose generation; the Loom is a bounded planning and coordination layer, not yet an independent six-model editorial team.

**v2 proposed:** tie the manuscript chapter's `insight_reference` to the Loom's primary focus and check consistency with a deterministic handoff; create immutable lesson packets from explicit editorial feedback.

**v3 proposed:** champion/challenger skill experiments using fixed, protected benchmarks; challengers make reviewable proposals and may never edit their own test criteria.

**v4 proposed:** isolated patch-generation/repair agents submitting draft PRs with human approval and regression tests; enforce separate budgets, review, policy, and rollback.

## Local commands

```bash
python3 -m unittest tests.test_witness_loom -v
python3 scripts/witness_loom.py --verify
python3 scripts/witness_loom.py --slot 2026-10-13T22Z
```

The GitHub Actions integration schedules one plan per UTC hour, subject to GitHub's best-effort schedule. A verified plan is not a verified source claim, a reviewed chapter, or proof of superior model intelligence.
